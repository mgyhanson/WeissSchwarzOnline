# ai：電腦對手

非官方的社群專案，與 Bushiroad 及各作品的權利人無關。

## 用法

```ts
import { createAi, createWorldSampler } from '@wso/ai';

const ai = createAi({ level: 'ADVANCED', card: (id) => getCard(id).def, deck: myDeckList, seed });
const view = getPlayerView(state, seat);            // 只有自己座位可以看到的資訊
const choice = ai.choose(view, view.decision.decision);

// 專家級：主機另外提供抽樣局面
const expert = createAi({ level: 'EXPERT', card, deck: myDeckList, seed });
expert.choose(view, view.decision.decision, createWorldSampler(state, seat, myDeckList));
```

## 四種難度

| 難度 | 檔案 | 方法 |
|---|---|---|
| 入門 | `src/beginner.ts` | 能出就出（只出到空枠）、能攻就攻，隨機選合法目標 |
| 普通 | `src/heuristic.ts` | 評分規則：角色強度、按 Power 比較選擇攻擊方式、安全時才放 Clock、助太刀只在能救回角色時使用 |
| 進階 | `src/heuristic.ts` | 普通級再加：Climax Combo、換上較強角色、保留 3 Stock 作 Encore、Level Up 時按手牌所需顏色、按公開資訊估計 Cancel 機率、對手傷害達 21 或以上時全力進攻 |
| 專家 | `src/expert.ts` | 主要階段、Climax、攻擊、Clock、Counter、Level Up：取進階級最好的幾個答案（最多 6 個，另加「不做」），在 6 個抽樣局面中各自模擬到下一回合結束，雙方都按進階級行動，選估計勝率最高的。每個答案用同一批局面比較 |

## 局面評分是學習得來的

專家用局面評分（`src/evaluate.ts`）判斷模擬結束時的局面好壞。評分不是人手估計的，而是從對局數據學習：

- 由兩個進階級對戰 3000 局。
- 記錄每回合開始時雙方視角的公開特徵（`src/features.ts`：傷害、手牌、Stock、場上角色等）及最後誰勝出。
- 用邏輯迴歸（logistic regression）擬合「勝出機會」。共 85,478 個局面，預測勝方的準確率為 66%。
- 重新擬合：`npm run ai:fit`，再把印出的權重抄到 `evaluate.ts`。卡池改變後應重新擬合。

這是量度後才改的。最初的評分是人手寫的：1 點傷害 = 10 分、每張手牌 = 3 分。用它的專家對進階 200 局只贏 93 局（46.5%），不比進階強。

學習得到的權重顯示，1 張手牌約等於 1 點傷害，Stock 更有價值；人手評分把手牌低估了三倍，令專家避免放 Clock。改用學習得到的評分後，同樣的 200 局（相同種子）贏 131 局（65.5%）。

## 不作弊

- 入門、普通、進階只取得 `PlayerView` 及待決定的 `Decision`，和真人玩家一樣。
- 專家級的抽樣局面（`src/sampler.ts`）由主機產生。主機把 AI 看不到的**每一張**卡換掉：
  - 自己的卡：自己的卡表減去看得到的卡，次序隨機（玩家知道自己的卡表）；
  - 對手的卡：約 8 張 Climax 減去已公開的 Climax，其餘用對手已公開過的卡；從未見過時用沒有能力的替身卡；
  - 亂數狀態也換掉，所以之後的洗牌及抽牌同樣未知。
- 抽樣只讀取卡在哪裡、表向還是裏向（公開資訊），從不讀取看不到的卡是甚麼。
- 測試（`tests/ai.test.ts`）在多個對局中途的局面，製作「只在 AI 看不到的部分不同」的另一局：自己看不到的卡換了次序，對手看不到的卡全部換成別的卡，亂數也不同。兩局的抽樣結果完全相同，專家的選擇也完全相同。
- 這些測試曾以故意加入的四種洩漏驗證，四種都會令測試失敗：保留對手真正的手牌、保留自己山札真正的次序、保留真正的亂數、按對手真正的 Climax 數目抽樣。

注意：「約 8 張 Climax」是假設（大部分卡組都放滿 8 張），不是 AI 知道的事實。

## 勝率

`npm run ai:tournament`。座位及卡組輪流交換，每個難度用兩副卡組、坐兩個座位的次數相同。

「明顯較強」的標準：較高難度的勝局要比一半多出至少兩個標準誤差。200 局即至少 115 勝（57.5%），由公平擲幣的機會率決定，不是按結果調整的數字。

最近一次結果（2026-11-12）：

| 對戰 | 局數 | 較高難度勝率 | 每局時間 |
|---|---|---|---|
| 普通 對 入門 | 200 | 75.5% | 約 0.03 秒 |
| 進階 對 普通 | 200 | 62.5% | 約 0.03 秒 |
| 專家 對 進階 | 200 | 66.5% | 約 5 秒 |

進階級的每項改良都可以獨立開關（`Features`）。曾把每一項單獨加到普通級、或單獨從進階級拿走，各與普通級對戰 200 局：「對手接近落敗時全力進攻」幫助最大；「假設對手一定會用助太刀」及「較保守地放 Clock」量度後反而有害，已刪除。其餘各項的效果在 200 局的誤差範圍內。

## 測試

- 入門、普通、進階兩兩對戰，專家對入門及進階：每個答案都被引擎接受，每 10 個決定檢查一次不變量，全部分出勝負。
- 同一種子得到完全相同的對局。
- 進階對入門 40 局，至少贏 28 局。
- 抽樣局面：AI 看到的內容與真實對局完全相同；是合法的遊戲狀態；自己的卡來自自己的卡表；上述不作弊測試。

## 已知限制

- 只用兩副 Trial Deck 調校及量度，卡池擴大後要重新量度。
- 專家級每步思考時間中位數約 0.04 秒，最長約 0.3 秒（2026-11-12 量度）；在瀏覽器主執行緒運行時畫面會短暫停頓；STEP 9 會改在伺服器運行。
- 專家只模擬到下一回合結束，長遠計劃（例如為兩回合後的斬殺保留資源）只靠評分規則。
