# STEP 9：網上對戰（伺服器、房間、重新連線、重播）

分支：`feat/step9-online`（由 `feat/card-pool-2` 開出）。日期：2026-11-12。

完成標準（`docs/03-phase1-plan.md`）：「Playwright 雙瀏覽器測試通過，包括重新整理及斷線」。結果見第 8 節。

## 1. 怎樣使用

### 在這部電腦上（兩個瀏覽器分頁，或與自己測試）

```bash
npm run server
```

然後打開 http://localhost:8787 。這個指令會先建立介面，再啟動伺服器；伺服器同時提供介面及對局連線。

### 與同一 Wi-Fi 的朋友（或自己的手機）

```bash
npm run server:lan
```

終端機會列出「同一網絡」網址（例如 `http://192.168.x.x:8787`），在對方的電腦或手機打開即可。這部 Mac 要保持開機，macOS 可能會問是否容許 Node 接受連線。

### 開發時

```bash
npm run server:dev
```

```bash
npm run dev
```

介面在 http://localhost:5173（修改程式碼即時更新），`/ws` 經 Vite 轉到 8787 埠的伺服器。

### 對局流程

1. 主頁或上方的「網上對戰」→ 輸入名稱、選卡組 →「建立房間」。
2. 把房間代碼（6 個字元）或邀請連結傳給朋友。朋友打開連結，代碼會自動填好，按「加入房間」。
3. 雙方按「準備」，對局開始，先後攻由系統隨機決定。
4. 結束後可以「再戰」（雙方都按才開始，之前可以換卡組）、「下載重播檔」或「觀看重播」。

## 2. 架構

```
瀏覽器 A ──WebSocket /ws──┐
                          ├── backend/（房間 → Match（引擎）→ 每個座位一個 SeatFeed）── SQLite
瀏覽器 B ──WebSocket /ws──┘
```

| 檔案 | 內容 |
|---|---|
| `backend/src/shared/` | 伺服器及瀏覽器共用、不依賴 Node 的程式：`protocol.ts`（訊息格式及驗證）、`match.ts`（種子＋行動列表＝一局）、`feed.ts`（每個座位收到的事件及更新）、`replay.ts`（重播檔格式及核對） |
| `backend/src/rooms.ts` | 房間、座位、準備、對局、再戰、重新連線、斷線保留。不含網絡程式碼，測試可以直接操作 |
| `backend/src/store.ts` | 持久化：Node 內建的 `node:sqlite`，資料庫在 `data.nosync/server.sqlite`（iCloud 不同步、不入 Git） |
| `backend/src/server.ts` | HTTP 及 WebSocket（`ws` 8.22.0）、來源檢查、心跳、提供已建置的介面 |
| `web-client/src/host/remote.ts` | 瀏覽器的連線（自動重新連線、心跳）及網上對局的 `GameHost` |
| `web-client/src/host/replay.ts` | 重播檢視器的 `GameHost` |
| `web-client/src/components/Online.tsx`、`ReplayScreen.tsx` | 大廳及重播畫面 |

對戰畫面本身沒有改動規則或顯示方式：單機、網上及重播都經同一個 `GameHost` 介面（`web-client/src/host/types.ts`）提供玩家視圖及事件。

### 伺服器權威及隱藏資訊

- 引擎只在伺服器運行。瀏覽器只送出「我選這個答案」，只收到自己座位的 `PlayerView` 及已按座位過濾的事件（`redactEvent`），與單機版相同。
- 種子在對局結束前只存在伺服器；重播檔（含種子）只在對局結束後才發出。
- 大廳不會告訴你對手選了哪副卡組。
- 測試逐條檢查兩個瀏覽器收到的每一則訊息：對手手牌、雙方山札及 Stock 一律隱藏，而且沒有種子（INV-06）。

### 重複及過期的答案

每個答案都附上決定編號（`decisionId`）及對局編號。伺服器只接受「現在待決定、屬於這名玩家」的答案；重複、遲到、別人的、不合法的答案一律拒絕，狀態完全不變。瀏覽器亦會阻止同一個決定送出兩次。

## 3. 平台規則（不是 Weiß Schwarz 的遊戲規則）

介面的「說明」及通知都會清楚寫明：

| 規則 | 預設 | 設定 |
|---|---|---|
| 一方斷線、另一方在等候時，斷線的一方要在限時內回來，否則系統代他投降（按 CR-1.2.4 投降處理） | 10 分鐘 | `GRACE_MINUTES` |
| 雙方都斷線時對局一直保留，不會判負 | — | — |
| 對局中按「離開房間」等於投降 | — | — |
| 沒有人連線而且 24 小時沒有使用的房間會被刪除 | 24 小時 | `RoomManager` 的 `roomTtlMs` |

## 4. 重新連線

- 每個座位有一個隨機的連線憑證（128 位元），存在瀏覽器的 localStorage；伺服器只保存它的 SHA-256。
- 重新整理頁面：頁面打開時自動回到座位，棋盤直接顯示目前局面，不重播已發生的動畫。
- 連線中斷：瀏覽器每 5 秒送出心跳，12 秒沒有回應就當作斷線，以 0.5、1、2、4、5 秒的間隔自動重試；回來後只補送錯過的更新，並照常播放動畫。
- 伺服器每 15 秒以 WebSocket ping 檢查連線，找出沒有正常關閉的連線（例如對方的網絡突然斷了）。

## 5. 持久化及伺服器重啟

資料庫只保存房間資料，以及每局的種子、卡組及行動列表，不保存遊戲狀態。伺服器啟動時按這些資料重新計算每一局（引擎是確定性的），結果與重啟前完全相同（有測試以 `serializeState` 比對）。

## 5b. 卡圖

伺服器把 `card-assets/local.nosync/`（或 `USER_ART_DIR` 指定的資料夾）的卡圖提供給所有連線的玩家，所以對手及同一 Wi-Fi 的裝置不需要自己有圖片。圖片不在 Git 內：在另一部電腦當伺服器時要自行複製這個資料夾，否則所有人看到程式繪製的卡面（遊戲照常運作）。

| `USER_ART` | 誰得到圖片 |
|---|---|
| `clients`（預設） | 所有連到伺服器的瀏覽器 |
| `local` | 只有這部電腦以 localhost 打開的瀏覽器 |
| `off` | 不提供 |

例如只限本機：`USER_ART=local npm run server:lan`。啟動時終端機會顯示圖片張數及目前的設定。詳見 [reports/CARD_IMAGE_REPORT.md](../reports/CARD_IMAGE_REPORT.md)。

## 6. 重播

- 重播檔是 JSON：種子、雙方 50 張卡的完整列表、每一個行動、結果、規則版本、玩家名稱。
- 檔案在對局結束後才可下載（網上及單機對局都可以）。
- 「重播」頁面讀取檔案時會先核對：格式、每張卡都在資料庫內、每個行動都被目前的引擎接受。日後規則引擎或卡牌資料改變而令行動不再合用時，會清楚說明無法重播，而不是顯示錯誤的局面。
- 可以選擇以任何一方的視角觀看，只顯示那名玩家當時看到的資訊；可以播放、暫停、逐步、跳到結尾。

## 7. 安全措施

| 風險 | 做法 |
|---|---|
| 其他網頁暗中連線到你的伺服器 | WebSocket 只接受與伺服器同一主機名稱或 localhost 的頁面（`ALLOWED_ORIGINS` 可加入其他來源） |
| 惡意或錯誤的訊息令伺服器停止 | 每則訊息先驗證格式（`parseClientMessage`）；引擎呼叫全部包在保護之內，錯誤的答案不會改變狀態；訊息上限 64 KB |
| 大量訊息 | 每個連線 10 秒內最多 200 則，超過即中斷 |
| 大量房間 | 最多 500 個房間 |
| 讀取伺服器上的其他檔案 | 靜態檔案只限介面資料夾內，測試包括 `..` 等路徑 |
| 經卡圖服務讀取其他檔案 | `/user-art/` 只提供 `image-index.json` 列出的圖片，而且檔名必須完全相同；清單只有卡號→檔名及來源說明 |
| 卡圖洩漏隱藏的卡 | 圖片不經對局訊息傳送；瀏覽器只為自己已知卡號的卡要求圖片，卡背不帶圖片（`npm run qa:online` 實測每個圖片請求） |
| 名稱 | 去除控制字元，最多 16 個字元；介面以文字顯示，不會當作 HTML |
| 憑證外洩 | 資料庫只存雜湊；憑證只在自己的瀏覽器 |

沒有帳號、密碼或任何 API Key。

| 測試 | 內容 | 結果 |
|---|---|---|
| `backend/tests/rooms.test.ts`（16 個） | 大廳、代碼、名稱清理；兩個 AI 經協定打完整局，逐則檢查隱藏資訊及種子；重複／過期／他人／不合法答案；投降；重播只在結束後發出並可重現；再戰；離開；重新整理及短暫斷線的恢復；斷線保留、及時回來取消、雙方斷線時不判負；房間過期；SQLite 重啟後局面完全相同並可繼續打完 | 全部通過 |
| `backend/tests/server.test.ts`（4 個） | 真正的 WebSocket：兩個連線打完整局（超過 50 個答案，正常結束）；斷線後以新連線回到座位；來源檢查；靜態檔案及路徑安全 | 全部通過 |
| `web-client/tests/online.test.ts`（3 個） | 瀏覽器的連線程式對真正的伺服器：自動代打打完整局，途中一方「重新整理」、另一方連線被切斷後自動重連；雙方結果相同；重播檢視器跳到結尾得到同一結果；房間已不存在時清除座位；同一決定按兩次只送出一次 | 全部通過 |
| `npm run qa:online`（Playwright，兩個真正的 Chromium，電腦及手機尺寸） | 見下 | 通過 |

`npm run qa:online` 的檢查項目（全部通過）：

1. Alice 建立房間，邀請連結顯示；Bob 打開邀請連結，代碼自動填好，加入；雙方準備，兩個畫面都開始對局，棋盤顯示對手名稱。
2. Bob 在第 3 回合重新整理頁面，直接回到對局。
3. Alice 的瀏覽器離線：她的畫面顯示連線中斷、對局保留；重新上線後自動重連。
4. Alice 關閉分頁：Bob 看到「對手斷線、約幾分鐘內未回來會被判投降」；Alice 重新打開網站，直接回到對局；Bob 的通知消失。
5. 雙方以自動代打打到結束，一方顯示勝出、另一方顯示落敗。
6. 下載重播檔（三次執行為 162 至 221 個行動）；在重播檢視器跳到結尾，結果相同。
7. 再戰：第二局在兩個畫面開始；Bob 關閉瀏覽器不再回來，保留時間（測試設為 25 秒）過後，Alice 以對手投降勝出，畫面說明原因。
8. 兩個瀏覽器收到的所有訊息都沒有隱藏資訊或種子；沒有頁面錯誤。

另外：`npm run check` 472 個測試通過（8 個慢速測試按設計略過）；單機 `npm run qa:ui` 仍然 60 fps、整局沒有錯誤。

### 測試中發現並修正的問題

- 重播「跳到結尾」後，對局紀錄只顯示開頭幾行：不播放動畫的更新沒有推進紀錄。已修正（`presentation/queue.ts`），並加入回歸測試（已確認沒有修正時會失敗）。
- Chromium 的「離線」模擬只擋住頁面的訊息，連線本身仍在，伺服器的心跳仍收到回應，所以伺服器察覺不到這種「離線」。瀏覽器一方的處理正確（察覺、顯示、自動重連）。真正的網絡中斷時心跳會停止，伺服器在 15 至 30 秒內察覺。伺服器一方的斷線處理改以關閉分頁測試。

## 9. 部署（需要你決定）

目前只做了本機及同一 Wi-Fi，沒有放到互聯網。要與不在同一網絡的朋友對戰，可以：

| 選項 | 做法 | 注意 |
|---|---|---|
| 通道服務（例如 Cloudflare Tunnel） | Mac 運行 `npm run server`，通道把公開網址轉到 8787 埠 | 免費；Mac 要開機；需要你自己的帳號及設定 |
| 雲端主機 | 伺服器放到雲端 | 每月數美元起 |

任何一種都等於向公眾提供含有官方卡牌文字的遊戲，版權風險明顯提高（見 `docs/03-phase1-plan.md` 第 4 節）。建議只與朋友以房間代碼使用、不公開宣傳。是否部署及用哪種方式由你決定；需要時我可以協助設定，但帳號要由你自己登入。

## 10. 未做或已知限制

- 單機對電腦仍在瀏覽器內運行（不經伺服器）；網上房間只供兩名真人玩家。
- 沒有觀戰、聊天、帳號或排名。
- 斷線倒數的分鐘數在收到房間更新時才更新，不會每秒跳動。
- 伺服器只保存每個房間「目前這一局」的行動；之前的局可在結束時下載重播檔保存。
