## 圖片驗證方法

不是只看副檔名：`scripts/images-lib.ts` 檢查 PNG 簽名、每個區塊的 CRC，並把圖像資料實際解壓，核對解壓後的大小與檔頭宣告的寬高相符。全部 609 張都是 PNG（角色及 Event 400×559 左右，Climax 是橫向 559×400 左右）。

## 圖片索引

`card-assets/local.nosync/image-index.json`：每張卡的檔名、SHA-256、位元組數、寬高、來源（整合包或官方卡表）、來源網址、記錄日期。`sources.json` 供介面顯示來源。`npm run cards:validate` 會核對索引、檔案及資料庫三者一致。

- Trigger Check、傷害判定等公開畫面、移動中的卡、區域檢視及重播也使用同一個卡面元件，所以同樣顯示真實圖片。

## 圖片的使用範圍（2026-11-14 更新）

你已表示取得使用這批卡圖的授權，並指示遊戲直接使用真實卡圖，包括其他裝置及網上房間的玩家。現在的做法：

**真實卡圖是遊戲的主要顯示方式**：卡牌一覽、卡牌詳情、卡組編輯器、手牌、舞台、Climax、Clock、Level、控え室、Trigger 及傷害判定的公開畫面、移動中的卡、重播，全部使用同一個元件（`CardFace`）顯示真實卡圖。程式繪製的卡面只在圖片不存在或載入失敗時作備用。

**圖片存放在哪裡**

- 609 張圖片只存放在**運行伺服器的那部電腦**的 `card-assets/local.nosync/`（可用 `USER_ART_DIR` 改到其他資料夾）。
- 不在 Git 版本庫內，沒有上傳到 GitHub（`.gitignore`），iCloud 不同步這個資料夾，`npm run build` 的輸出也不包含圖片。
- 所以：**換一部電腦 clone 這個專案不會有圖片**；要在另一部電腦當伺服器，需要自行把這個資料夾複製過去。其他裝置（手機、對手的電腦）不需要有圖片，它們由伺服器取得。

**圖片怎樣到達其他裝置**（`backend/src/user-art.ts`，遊戲伺服器及開發伺服器共用）

| 設定 `USER_ART` | 誰得到圖片 |
|---|---|
| `clients`（預設） | 所有連到這個伺服器的瀏覽器：這部電腦、同一 Wi-Fi 的裝置（`npm run server:lan`、`npm run dev:lan`）、網上房間的玩家 |
| `local` | 只有這部電腦以 localhost 打開的瀏覽器 |
| `off` | 不提供；所有人看到程式繪製的卡面 |

目前伺服器只在你的電腦或區域網絡運行，**沒有部署到互聯網**；如果日後部署到公開的伺服器，圖片就會隨伺服器公開提供，屆時請先確認授權範圍是否包括公開發佈（不想公開可設 `USER_ART=local` 或 `off`）。授權本身我無法核實，報告只記錄你的說明。

**安全措施**（`backend/tests/server.test.ts` 有 5 個測試）

- 只提供 `image-index.json` 列出的檔案，而且必須是完全相同的檔名：請求不能指定資料夾內外的任何其他檔案（`../`、編碼後的路徑、`image-index.json`、`sources.json` 本身都得到 404）。
- 卡號與檔案的對應只來自索引，不靠猜測檔名。
- 清單（`/user-art/manifest.json`）只包含卡號→檔名，以及這些檔案的來源說明；不包含資料夾路徑、雜湊值或其他檔案。
- 每張圖片有 ETag（SHA-256）及 `Cache-Control: private, max-age=86400`，瀏覽器可以快取，重複請求回覆 304。
- 自行放入的圖片要先用 `npm run cards:images:index` 登記到索引才會被提供（檔名必須是資料庫內的卡號，圖片必須可以解碼）。

**不會洩漏隱藏資訊**

- 圖片不經過對局訊息：`PlayerView` 及 `GameEvent` 完全沒有改動，裏面沒有任何圖片資料。
- 瀏覽器只會為自己的 `PlayerView` 中**已知卡號**的卡要求圖片；背面的卡（對手手牌、山札、Stock）沒有卡號，畫的是卡背，不會發出任何圖片請求。
- 瀏覽器測試（`npm run qa:online`）實際核對：開局時雙方只要求過自己卡組的圖片；整局之中每一個圖片請求都屬於伺服器已經向該玩家公開的卡；卡背從未帶有圖片。
